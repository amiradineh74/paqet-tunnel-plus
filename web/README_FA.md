# شاخه آزمایشی — Paqet Web Admin با دسترسی اینترنتی

این شاخه اولین بخش از پنل مدیریتی **اینترنتی** را پیاده‌سازی می‌کند؛ **هنوز تمام قابلیت‌های اسکریپت از وب در دسترس نیستند**. برای نقشه دقیق و شروط پذیرش، [WEB_ADMIN_SPEC_FA.md](WEB_ADMIN_SPEC_FA.md) را بخوانید.

## امکانات این مرحله
- همان رابط فارسی وب و نمایش وضعیت محلی، تنظیمات خلاصه و لاگ‌های سرویس.
- Start / Stop / Restart **تنها روی سرویس انتخاب‌شده** با تایید مجدد در مرورگر.
- اعتبارسنجی نام سرویس، بررسی اینکه unit متعلق به Paqet است، عدم اجرای shell دلخواه، قفل عملیات هم‌زمان و ثبت رخداد در فایل root-only.
- پروکسی اختیاری Caddy برای آدرس اینترنتی HTTPS با **رمز مدیر** و توکن داخلی؛ سرویس Python همچنان فقط روی 127.0.0.1 گوش می‌کند.
- آزمون‌های CI پایتون، Bash، جاوااسکریپت و تست پرچم‌ها.

## دسترسی اینترنتی — آزمایشی، برای سرور اصلی هنوز توصیه نمی‌شود
1. دامنه‌ای مانند panel.example.com که رکورد DNS A آن به IP همین سرور اشاره کند لازم است.
2. Caddy نسخه 2.8 یا جدیدتر را از منبع معتبر سیستم نصب کنید. پورت‌های ورودی TCP 80 و 443 برای گواهی معتبر باید قابل دسترسی باشند.
3. پنل محلی را طبق گزینه **9 → 1** نصب کنید. گزینه **9 → 6**، پس از ورود دامنه، از شما رمز مدیر با حداقل 14 نویسه می‌خواهد.
4. Caddy قبل از reload اعتبار پیکربندی را بررسی می‌کند. کانفیگ قبلی بکاپ می‌شود و در صورت خطا بازیابی می‌شود.
5. در مرورگر، https://panel.example.com را باز کنید. مرورگر ابتدا نام کاربری **admin** و رمز تنظیم‌شده را می‌خواهد؛ پس از تأیید، پروکسی خودش توکن داخلی را به بک‌اند می‌دهد. **توکن را در مرورگر عمومی وارد نکنید.**
6. با دسترسی HTTPS، ورود از داخل رابط به‌طور خودکار انجام می‌شود؛ در صورت عدم ورود، DNS، اعتبار TLS، Caddy و سرویس محلی را بررسی کنید.

> **هشدار مهم:** این معماری هنوز شامل نقش‌های چندکاربره، MFA، rate-limiting پیشرفته، جداسازی دسترسی root به helper و کنترل دوطرفه rollback نیست. برای مدیریت اینترنتیِ تولیدی باید این موارد و تست سخت‌سازی تکمیل شوند. هیچ دستور shell یا SSH از مرورگر در این مرحله فراهم نشده.

## پوشش فعلی و موارد باقی‌مانده
Start/Stop/Restart هر سرویس، نمایش خلاصه و لاگ در این شاخه توسعه داده شده‌اند. این قابلیت‌ها **هنوز** پیاده‌سازی نشده‌اند: نصب کامل Client/Server از وب، مدیریت هم‌زمان دو سرور، ویرایش KCP/Flags و YAML، تست سرعت داخل تانل، اجرای Flag Auto-Test از وب، ابزارهای iptables و tcpdump، آپدیت و rollback هسته، بکاپ تنظیمات و سیستم هشدار.

## امنیت
- پورت داخلی 8792 را مستقیم روی IP عمومی باز نکنید. مدیریت عمومی فقط پشت پروکسی HTTPS و احراز هویت اجرا می‌شود.
- توکن داخلی در پیکربندی Caddy با مجوز root:caddy محفوظ است؛ Caddy برای هر درخواست Backend هدر Authorization آن را جایگزین می‌کند.
- سرویس root در این نسخه فقط عملیات \`systemctl start|stop|restart\` روی نام whitelisted اجرا می‌کند؛ برای انتشار عمومی نهایی بهتر است privileges را به helper محدود کنیم.
- گزارش اعمال عملیات: \`/opt/paqet-tunnel-plus/web-panel.audit.jsonl\` با دسترسی root و مجوز 0600.
- نصب این قابلیت **اختیاری** است و صرف اجرای install.sh یا به‌روزرسانی منوی اصلی هیچ‌گونه تغییر سرویس، YAML، هسته یا فایروال انجام نمی‌دهد.
- این نسخه هنوز با سرور واقعی در شرایط تولیدی آزموده نشده است.

## راهنمای نسخه قدیمی صرفاً محلی 0.1.1

**آزمایشی، اختیاری، فقط خواندنی.** این نسخه برای دسترسی عمومی روی اینترنت نیست.

ویژگی‌های «تست سرعت»، «اجرای تست پرچم از وب» و «مدیریت سرویس از وب» فعلاً فقط پیش‌نمایش هستند؛ هنوز اجرا نمی‌شوند.

## امکانات واقعی

- رابط فارسی واکنش‌گرا با پیش‌نمایش آفلاین؛ در حالت آنلاین وضعیت سرویس‌های محلی و نسخه هسته را می‌خواند.
- جدول سرویس‌ها با KCP mode، MTU، conn و TCP flags (بدون نمایش کلید).
- آخرین لاگ‌ها با محدودیت تعداد و سانسور اولیه بعضی اطلاعات حساس.
- API فقط GET، توکن اختصاصی، HTTP فقط روی 127.0.0.1.
- نصب سرویس جداگانه paqet-plus-web.service، مستقل از سرویس‌های اصلی Paqet.

**توجه:** سبز بودن وضعیت systemd به معنی سالم‌بودن انتقال داده از داخل تانل نیست.
تاریخچه تست‌های پرچم داخل رابط، نمونه ثبت‌شده تاریخی است و وضعیت لحظه‌ای نیست.

## نصب اختیاری از داخل اسکریپت اصلی

روی هر سرور به صورت جداگانه:

~~~bash
bash <(curl -fsSL https://raw.githubusercontent.com/amiradineh74/paqet-tunnel-plus/main/install.sh) --manage
~~~

از منوی Management / Diagnostics گزینه 9) Web Panel، سپس 1) Install or update and start panel را بزنید.

نصب معمول مدیریت، خودش پنل را نصب یا اجرا نمی‌کند؛ فقط با انتخاب گزینه ۹ و بعد ۱، نصب و فعال‌سازی انجام می‌شود. این عملیات نباید وضعیت هسته، KCP، YAML، سرویس‌های تونل یا فایروال را تغییر دهد.

در خروجی موفق باید paqet-plus-web.service فعال باشد. این سرویس از Python 3 استفاده می‌کند. پورت محلی پیش‌فرض 8792 است.

## باز کردن از مرورگر روی رایانه

از رایانه خودتان یک پنجره SSH جداگانه به همان سرور باز کنید:

~~~bash
ssh -L 8792:127.0.0.1:8792 root@SERVER_IP
~~~

آدرس را در Firefox یا Chrome وارد کنید:

~~~text
http://127.0.0.1:8792
~~~

در SSH همان سرور، توکن را بخوانید:

~~~bash
sudo cat /opt/paqet-tunnel-plus/web-panel.token
~~~

توکن را فقط در صفحه مرورگر خودتان وارد کنید. آن را در چت، عکس یا لاگ عمومی قرار ندهید.

برای سرور دوم می‌توانید پورت سمت رایانه را متفاوت انتخاب کنید:

~~~bash
ssh -L 8793:127.0.0.1:8792 root@SECOND_SERVER_IP
~~~

و در مرورگر http://127.0.0.1:8793 را باز کنید. این نسخه دو سرور را در یک صفحه تجمیع نمی‌کند.

## مدیریت و حذف فقط پنل

گزینه 9) Web Panel سپس:
- 1 نصب/بروزرسانی و اجرای وب
- 2 وضعیت و راهنمای اتصال
- 3 راه‌اندازی مجدد فقط پنل وب
- 4 توقف فقط پنل وب
- 5 حذف سرویس و فایل‌های اجرا؛ بدون حذف توکن و بکاپ‌ها

هیچ گزینه‌ای به PasarGuard یا قوانین فایروال دست نمی‌زند.

## اجرای تست‌های نرم‌افزاری

در نسخه کلون‌شده مخزن:

~~~bash
python3 -m unittest discover -s web -p 'test_*.py' -v
python3 -m py_compile web/web_panel.py
bash -n web/manage.sh
bash -n deploy.sh
~~~

## محدودیت‌های امنیتی و عملکرد

- فقط loopback و SSH forwarding؛ پورت 8792 را مستقیم عمومی نکنید.
- API صرفاً خواندنی است؛ حتی با توکن هیچ دستور Restart یا ویرایش YAML اجرا نمی‌کند.
- ارسال token با Bearer در یک اتصال HTTP محلی پس از SSH است، نه از اینترنت عمومی.
- سانسور لاگ‌ها محدود است؛ پیش از به‌اشتراک‌گذاری خروجی‌ها آن‌ها را بازبینی کنید.
- بک‌اند با سطح دسترسی root اجرا می‌شود تا فایل‌های سیستم و ژورنال را بخواند؛ این نسخه را روی میزبان ناشناس یا اینترنت عمومی نصب نکنید.
- نصب‌گر از branch اصلی مخزن public فایل دریافت می‌کند؛ برای محیط حساس بهتر است تغییرات را پیش از نصب بازبینی یا به commit مشخص pin کنید.
- هیچ عملیات تعویض هسته یا تغییر Flag/KCP به واسطه نصب پنل انجام نمی‌شود.

## توسعه بعدی

۱. احراز هویت چندکاربره و TLS برای انتشار امن.
۲. عامل مستقل در ایران و آلمان، تشخیص سلامت واقعی عبور داده و داشبورد تجمیعی.
۳. تست سرعت دوطرفه از مسیر داخلی Paqet با سقف حجم/زمان و ثبت RTT/Jitter.
۴. تغییر انتخابی پرچم‌ها و KCP همراه Snapshot/تأیید دوطرفه/rollback.
۵. گزارش رخدادها، آلارم قطعی، تاریخچه و صادرات CSV.

**اولویت پروژه:** تغییرات موفق باید پس از تست عملی مستند و وارد اسکریپت اصلی شوند؛ نسخه وب فعلی تنها فاز پایش است.
